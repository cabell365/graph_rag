01 / CANYON COMMONS

Purpose & decisions

Build an explorable Neo4j graph from the supplied directory and answer business questions through a Python Streamlit interface. Use local mistral:latest and nomic-embed-text:latest, with no cloud inference dependency.

29Business source documents
2,016,000Monthly financial observations

The supplied graph fixture gives deterministic relationships; no speculative LLM extraction is required for this corpus. Neo4j stores the full financial export for exact aggregate queries. Only text passages receive embeddings.

05 / CANYON COMMONS

Import & validation

  1. Inventory source files and SHA-256 hashes. Verify 29 manifest entries against original business documents.
  2. Extract Markdown, DOCX tables/paragraphs and workbook cells. Keep the separate workbook sample visibly labeled.
  3. Parse only known SQL INSERT tables. Reject unknown tables, null metric keys/amounts, duplicate natural keys and missing rep/month/year/team references. Validate month IDs.
  4. Create uniqueness constraints and text/vector indexes. Derive vector dimension from the actual Nomic embedding; reject a mismatched existing index.
  5. Import fixture entities and documented relations. Split and embed changed documents. Skip unchanged document hashes and model tags.
  6. Batch finance rows into stable metric IDs. Reconcile graph count to the backup and set a completion marker only after success.

Rerunning the same input is idempotent at the identity level. Source removals are not automatically pruned; use a fresh dedicated database for a changed dataset. Staging is replaced atomically, but the Neo4j import consists of multiple transactions. The finance completion marker prevents partial financial answers.

06 / CANYON COMMONS

Retrieval & temporal reasoning

Query embeddings and keyword results are fused with reciprocal rank fusion. Exact IDs and matching full entity names strengthen graph seeds. Bounded expansion excludes finance paths; supporting document IDs bring additional text into context. Retrieved graph edges are displayed only when their source documents are included, or when they are explicitly sourced from the backup.

The optional sidebar event date filters document validity. With no date, competing historical policies may be retrieved together and Mistral is instructed to ask for timing. A year in a finance question selects a finance period; it does not automatically set policy validity. Date filtering narrows evidence, not proof of a claim’s truth. Historical examples in DOC-011 may concern dates other than the document’s own validity and need careful reading.

No supplied policy is verified for 2025–2026. “Current” in an attachment means current within its scenario window.
07 / CANYON COMMONS

Exact financial answers

A conservative parser recognizes one explicit year, optional month, and a rep/team ID or explicit network scope. It rejects ambiguous periods, ranking, comparisons and customer/SKU requests. The Finance explorer supplies explicit filters directly. Query structure is fixed in Python; values are parameters.

MATCH (m:MonthlySales) WHERE m.year=$year
  AND ($month IS NULL OR m.month_id=$month)
  AND ($rep IS NULL OR m.sales_rep_id=$rep)
RETURN count(m), sum(m.target_sales), sum(m.actual_sales)

The tool computes attainment as 100 × total actual ÷ total target, with null for a zero denominator. A finance response includes source filename/hash, Cypher, filters and row count. Exact queries require the full import completion marker. The source has no orders, invoices, credits, customer allocations or product allocations.

08 / CANYON COMMONS

Interface & accessibility

The Knowledge Commons uses university green #275D38, deep forest backgrounds, ivory text and restrained serif headings. Chat streams answers, exposes source passages and relationship provenance, and exports a conversation with evidence. The library displays dates and origins. The finance workspace separates explicit filters from numeric results. Offline HTML guides use responsive layouts, labeled diagrams, local styling, print support and no third-party scripts.

10 / CANYON COMMONS

Known limits & evolution

The reference graph covers a small fictional pilot, while financial metrics cover the full dump. Unassigned reps do not gain invented customers. General graph expansion uses at most two bounded hops. Outreach questions add an explicit three-hop incident → product → customer → representative path, with source provenance and eligibility caveats. Workbook formulas are read from cached values and are not recalculated. DOCX images are not OCRed; the schema image is interpreted through its accompanying textual tables and the authoritative dump. LLM citations and arithmetic require evaluation; no automated source-overlap metric proves answer correctness.

Future work can add claim nodes with source spans and per-claim validity, authenticated users, structured workbook analytics, resumable checkpoints, a dedicated read-only runtime role and community summaries for broader corpus questions. None is assumed by the current chatbot.

RRFReciprocal rank fusion: combine ranked vector and keyword results without comparing their raw scores.

BoltThe database protocol used by the Python driver.
FixtureA supplied reference graph describing this fictional scenario; it is not newly inferred truth.
